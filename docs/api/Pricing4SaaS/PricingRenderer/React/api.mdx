:::info
Currently, the pricing renderer is specifically designed for the [Pricing2Yaml 3.1 specification](../../../pricing-description-languages/Pricing2Yaml/versions/pricing2yaml-v31-specification.mdx).

Nonetheless, we provide **PARTIAL** support for the [Pricing2Yaml 3.0 syntax](../../../pricing-description-languages/Pricing2Yaml/versions/pricing2yaml-v30-specification.mdx).
The renderer will use all the syntax of [Pricing2Yaml 3.0](../../../pricing-description-languages/Pricing2Yaml/versions/pricing2yaml-v30-specification.mdx)
compatible with Pricing2Yaml 3.1 specification. You will see a warning message in the renderer that emphasizes this fact.
:::

In order to use the `PricingRenderer` component you have to provide an iPricing method input to the renderer.
You **MUST** choose only one method to configure the `PricingRenderer` input:
- Use `pricing` prop if you provide a **JavaScript object** compatible with the [Pricing2Yaml 3.1 specification](../../../pricing-description-languages/Pricing2Yaml/versions/pricing2yaml-v31-specification.mdx).
- Use `src` prop if you provide a **URL** (HTTP or HTTPS only) where the Pricing2Yaml is exposed.
- Use `yaml` prop if you provide a **string** encoded in [Pricing2Yaml 3.1 specification](../../../pricing-description-languages/Pricing2Yaml/versions/pricing2yaml-v31-specification.mdx).

### ctaEnabled

:::warning
You can configure call-to-actions (CTAs) exclusively for plans.
:::

If you have configured call-to-actions (CTAs), the **boolean** `ctaEnabled`
prop controls whether they are displayed in the `PricingRenderer`.
- When `ctaEnabled` is `true`, the CTAs are rendered.
- when `ctaEnabled` is `false`, the CTAs are not rendered.
- `ctaEnabled` defaults to `true`

#### Signature

[View source](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/react/index.ts#L70).
```typescript

```

#### Details

```jsx
<PricingRenderer pricing={pricing} ctaEnabled={false} />
```

### defaultSelection

With the `defaultSelection` prop you can set which plans and add-ons are selected by default on the `PricingRenderer`.
You can also customize the default billing period and the default values for variables.

#### Signature

[View source](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/react/index.ts#L63).
```typescript
defaultSelection?: Partial<PricingSelection>
```

#### Properties

```typescript
interface PricingSelection {
  planId?: string;
  billingPeriod?: string;
  variables: Record<string, unknown>;
  addOns: Record<string, AddOnSelection>;
}
```

The `PricingSelection` structure is composed of:
- `planId` (**optional**): the `planId` is the
**key name** of a plan defined inside the Pricing2Yaml [`plans`](../../../pricing-description-languages/Pricing2Yaml/versions/pricing2yaml-v31-specification.mdx#plans)
map. The type of `planId` is a string.
- `billingPeriod` (**optional**): the `billingPeriod` is the **key name** of a billing period defined
inside the Pricing2Yaml [`billing`](../../../pricing-description-languages/Pricing2Yaml/versions/pricing2yaml-v31-specification.mdx#billing) map.
The type of `billingPeriod` is a string.
- `variables` (**optional**): an object in which the property names of the object are the key names of
the variables defined inside the Pricing2Yaml [`variables`](../../../pricing-description-languages/Pricing2Yaml/versions/pricing2yaml-v31-specification.mdx#variables)
map and values are the default values for the *Configure your pricing* section.
- `addOns` (**optional**): an object in which the property names of the object are the key names of
an add-on inside the Pricing2Yaml [`addOns`](../../../pricing-description-languages/Pricing2Yaml/versions/pricing2yaml-v31-specification.mdx#addons)
map. Each key of the object must map to an object of type [`AddOnSelection`](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/core/types.ts#L157-L160).
The type of `addOns` is a `Record<string, AddOnSelection>`.

  An object of type [`AddOnSelection`](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/core/types.ts#L157-L160)
  has two properties `selected` and `quantity`. The `selected` property indicates if the add-on is selected.
  The `quantity` property indicates how many add-ons are contracted.

  [`AddOnSelection` source code:](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/core/types.ts#L157-L160)
  ```typescript
  interface AddOnSelection {
    selected: boolean;
    quantity: number;
  }
  ```

#### Examples

In this section we will explain in detail how to configure `defaultSelection` object.

Here is a quick example using the [CCSIM](https://sphere.score.us.es/static/pricings/uploaded/CCSIM/1.0.yml)
as reference for how to use the `defaultSelection` prop:
```jsx
import CCSIM from "./ccsim.js"

const initialSelection = {
    planId: "ENTERPRISE",
    billingPeriod: "annual",
    addOns: {
      extraProject: {
        selected: true,
        quantity: 1
      },
      uiTests: {
        selected: true,
        quantity: 1
      }
    }
  }
<PricingRenderer pricing={CCSIM} defaultSelection={initialSelection} />
```


**Selecting a plan**

To show how to select a plan by default, we will be using the [CCSIM](https://sphere.score.us.es/static/pricings/uploaded/CCSIM/1.0.yml)
pricing stored in SPHERE (pricing repository).

We will configure the `PricingRenderer` with the *PRO* plan. Take the key name of the *PRO*
plan defined in [CCSIM](https://sphere.score.us.es/static/pricings/uploaded/CCSIM/1.0.yml)
and store it in an object with a property called `planId`. Then pass this object to the `defaultSelection` prop:
```jsx
import CCSIM from "./ccsim.js"

const intialSelection = {
  planId: "PRO"
}

<PricingRenderer pricing={CCSIM} defaultSelection={initialSelection} />
```

**Selecting a billing period**

To show how to select a billing period by default, we will be using the [CCSIM](https://sphere.score.us.es/static/pricings/uploaded/CCSIM/1.0.yml)
pricing stored in SPHERE (pricing repository).

We will configure the `PricingRenderer` with an *annual* billing period. Take the key name of the *annual*
billing period defined in [CCSIM](https://sphere.score.us.es/static/pricings/uploaded/CCSIM/1.0.yml)
and store it in an object with a property called `billingPeriod`. Then pass this object to the `defaultSelection` prop:
```jsx
import CCSIM from "./ccsim.js"

const intialSelection = {
  billingPeriod: "annual"
}

<PricingRenderer pricing={CCSIM} defaultSelection={initialSelection} />
```

**Selecting default values for defined variables**

:::warning
If [`variablesEnabled`](#variablesenabled) is set to `true` all variable controls will be disabled and
the values in the `variables` object will not take effect.
:::

To show how to select default values for defined variables, we will be using the [CCSIM](https://sphere.score.us.es/static/pricings/uploaded/CCSIM/1.0.yml)
pricing stored in SPHERE (pricing repository).

Imagine that you want to base your pricing on the number of seats and, for convenience,
provide a default number of seats (e.g., 5).

Given that the formula for the *PRO* plan is 239 * #seats, you would need to create an object
with a `seats` property set to `5` (The type of the value must match the type expected by the formula):


```jsx
import CCSIM from "./ccsim.js"

const intialSelection = {
  variables: {
    seats: 5
  }
}

<PricingRenderer pricing={pricing} defaultSelection={initialSelection} />
```

**Selecting add-ons**

To show how to select add-ons by default, we will be using the [CCSIM](https://sphere.score.us.es/static/pricings/uploaded/CCSIM/1.0.yml)
pricing stored in SPHERE (pricing repository).

We will configure the `PricingRenderer` with *Extra Project* and *UI Tests* add-ons.
Use the key names defined for these add-ons in [CCSIM](https://sphere.score.us.es/static/pricings/uploaded/CCSIM/1.0.yml)
as the keys of the [`addOns`](../../../pricing-description-languages/Pricing2Yaml/versions/pricing2yaml-v31-specification.mdx#addons)
map, *Extra Project* is named as `extraProject` and *UI Tests* is named `uiTests`.
Each key must map to an [`AddOnSelection`](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/core/types.ts#L157-L160)
object. Configure `selected` with the value `true` and a numeric value for `quantity` indicating the count of
add-ons desired. The resulting configuration will be:
```jsx
import CCSIM from "./ccsim.js"

const intialSelection = {
  addOns: {
    extraProject: {
      selected: true,
      quantity: 1
    },
    uiTests: {
      selected: true,
      quantity: 1
    }
  }
}

<PricingRenderer pricing={CCSIM} defaultSelection={initialSelection} />
```

that can be used inside any formula.

[View source](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/core/types.ts#L38-L40).
```typescript
interface ExpressionOptions {
  functions?: Readonly<Record<string, ExpressionFunction>>;
}
```

[View source](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/core/types.ts#L36).
```typescript
type ExpressionFunction = (...argumentsList: unknown[]) => unknown;
```

#### Details

To make a custom function available to a formula, define it in the `functions` property
of the expression options object. Each key of the object will be the function name
that you can use globally.

Given the formula `volumePrice(#seats)`, `volumePrice` will be called with the variable `seats`
as an argument:
```jsx
const exOpts = {
  functions: {
    volumePrice: (units) => Number(units) * 0.8
  }
}

<PricingRenderer pricing={pricing} expressionOptions={exOpts} />
```

### layout

The `layout` prop controls the visualization display mode of the `PricingRenderer`.

#### Signature

[View source](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/react/index.ts#L74).
```typescript
layout?: 'auto' | 'compact' | 'table'
```

- When `layout` is `auto`, the pricing renderer changes between the `table` and `compact` layout
using the width available in the screen.
- When `layout` is `compact`, features and usage limits will be displayed using a comparison table.
- When `layout` is `table`, features and usage limits will be displayed as independent items.
- `layout` defaults to `auto`

#### Details

```jsx
<PricingRenderer pricing={pricing} layout="compact" />
```

### loadPricing

The `PricingRenderer` has a built-in loader to fetch a pricing but is quite limited. However, you
can implement your own workflow to get a pricing. This is useful if:
- You need a custom authentication process
- You need to access Cloud Storage Services like: [Amazon S3](https://aws.amazon.com/es/s3/),
[Google Cloud Storage](https://cloud.google.com/storage), [Alibaba Cloud Object Storage Service](https://www.alibabacloud.com/en/product/object-storage-service) or any provider
- You use a certain SDK to fetch your pricing

:::note
The default built-in loader has the following restrictions:
- Permits only HTTP or HTTPS `GET` only
- The internal `fetch` method uses `credentials: "omit"`, meaning credentials will not be sent in the request or
included in the response.
:::

#### Signature

[View source](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/yaml/types.ts#L24)
```typescript
(context: PricingLoaderContext) => Promise<string | IPricingLike>
```

The `loadPricing` function takes one parameter `context` of type [`PricingLoaderContext`](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/yaml/types.ts#L16-L22)
and returns a promise that resolves to a string or a [`IPricingLike`](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/core/types.ts#L3-L18)
object

#### Parameters

`context`: `PricingLoaderContext`

[`PricingLoaderContext` source code](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/yaml/types.ts#L16-L22):
```typescript
interface PricingLoaderContext {
  url: string;
  signal: AbortSignal;
  request: Omit<PricingRequestOptions, 'headers' | 'fetch'> & {
    headers?: HeadersInit;
  };
}
```

#### Details

Imagine that we have the following implementation of a pricing loader function. This function implementation
includes a `Bearer` token in the `Authorization` header to access a private resource:
```javascript
const customLoadPricing = async (context) => {
  const authorizationToken = await getAccessToken();

  const response = await fetch(context.url, {
    method: "GET",
    signal: context.signal,
    headers: {
      Authorization: `Bearer ${authorizationToken}`,
    },
  });

  if (!response.ok) {
    throw new Error(`Failed to load pricing: ${response.status}`);
  }

  return response.text();
};
```

You can pass the previous `customLoadPricing` function to the `loadPricing` prop of the `PricingRenderer`:
```jsx
<PricingRenderer src="https://acme.cloud.com/pricings/2026.07-foo.yaml" loadPricing={customLoadPricing} />
```

In this example we are passing the `adapter` function to a `PricingSyntaxAdapter` object.
This adapter changes the `saasName` by appending the `createdAt` to the `saasName`
property of the Pricing2Yaml:
```jsx
const adapter = (pricing) =>
  ({...pricing, saasName: `${pricing.saasName} (${pricing.createdAt})`})

    {
      id: "adapter1",
      supports: (syntaxVersion) => syntaxVersion === "3.1",
      adapt: adapter
    }
  ]
}

<PricingRenderer pricing={pricing} normalizeOptions={normOpts} />
```

### onAction

The `onAction` prop takes a [`PricingActionEvent`](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/element/events.ts#L34)
handler function.
The `onAction` function callback is executed if the user triggers a call-to-action (CTA)
of a plan. For example clicking on `Choose X`/`Start with X` will trigger the `onAction`
callback. However, you can define your own CTAs in the [`presentation.ctas`](#presentation) object.

#### Signature

[View source](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/react/index.ts#L83)
```typescript
onAction?: (event: PricingActionEvent) => void
```

This function is defined with one parameter `event` of type [`PricingActionEvent`](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/react/index.ts#L83),
an alias of a [`CustomEvent`](https://developer.mozilla.org/en-US/docs/Web/API/CustomEvent)
with [`PricingActionDetail`](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/element/events.ts#L19-L26) data
attached, and must return `void`.

#### Parameters

`event`: `PricingActionEvent` (alias of `CustomEvent<PricingActionDetail>`)

[View `PricingActionDetail` source](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/element/events.ts#L19-L26):
```ts
interface PricingActionDetail {
  actionId: string;
  planId?: string;
  href?: string;
  selection: PricingSelection;
  resolved: ResolvedPricing;
  metadata?: UnknownRecord;
}
```

#### Details

In this example, each time that the user clicks on the `Choose X` plan section, the
`handleRendererAction` handler logic will be executed.
```jsx
const handleRendererAction = (customEvent) =>
  registerPlanSelected(customEvent.detail.actionId, customEvent.detail.planId)

<PricingRenderer onAction={handleRendererAction} />
```

:::info
To access the [`event`](https://developer.mozilla.org/en-US/docs/Web/API/CustomEvent) information
access `event.detail` object.
:::

### onDiagnostic

A [`PricingDiagnosticEvent`](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/element/events.ts#L35) handler function.
This function will be triggered if:

### onSelectionChange

A [`PricingSelectionChangeEvent`](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/element/events.ts#L33)
handler function. This function callback is called every time that the pricing selection changes or
a variable that is involved in the computation of the final price changes.

The following list enumerates some actions that affect the pricing selection:
- Change the billing period.
- Add or remove a plan. In the `Plans` section, click inside a plan card or click in the `Select` button
to include a plan. You can select another plan by clicking on a different card.
- Add or remove an add-on. In the `Add-ons` section, click `Add` to include an add-on and click again to remove it.
- Change the quantity of add-ons contracted.
- Confirm dependencies changes or conflicts between add-ons.

These are some actions that affect the variables of a pricing:
- Modifying a customizable variable.
- Resetting all the customizable variables to the default values. Just click on
the `Reset` button in the `Configure your pricing` section.

:::warning
Configured Call to Actions (CTAs) do not trigger the `onSelectionChange` event.

### request

This prop accepts a **JavaScript object** of type [`PricingRequestOptions`](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/yaml/types.ts#L8-L14).

[`PricingRequestOptions` source code:](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/yaml/types.ts#L8-L14)
```typescript
interface PricingRequestOptions {
  headers?: HeadersInit | (() => HeadersInit | Promise<HeadersInit>);
  credentials?: RequestCredentials;
  timeoutMs?: number;
  maxBytes?: number;
  fetch?: typeof globalThis.fetch;
}
```

#### Properties

`headers` (**optional**):
- Accepts a [`Headers`](https://developer.mozilla.org/en-US/docs/Web/API/Headers) like object
- Accepts a function that returns a `Headers` like object
- Accepts an async function that returns a promise containing [`Headers`](https://developer.mozilla.org/en-US/docs/Web/API/Headers)
or [`Headers`](https://developer.mozilla.org/en-US/docs/Web/API/Headers) like object

Example of a [`Headers`](https://developer.mozilla.org/en-US/docs/Web/API/Headers) like object
```javascript
const customHeaders = {
  'Content-Type': 'application/json',
  'Authorization': 'Bearer <REDACTED>'
}
```

Example of a function that returns a [`Headers`](https://developer.mozilla.org/en-US/docs/Web/API/Headers) like object:
```javascript
const customHeaders = () => ({
  'Content-Type': 'application/json',
  'Authorization': 'Bearer <REDACTED>'
})
```

Example of an async function that returns a promise containing `Headers` or `Headers` like object
  ```javascript
  const customHeaders = async () => ({
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${await refreshAccessToken()}`
  })
  ```
`credentials` (**optional**): string

Whether or not the browser sends credentials with the request. Accepted values are:
  - `omit`
  - `same-origin`
  - `include`

`timeoutMs` (**optional**): number

Maximum time to wait for the download in milliseconds (Default is 15000 ms)

`maxBytes` (**optional**): number

Maximum number of bytes to be interpreted by the renderer (Default is 2 MiB).

`fetch` (**optional**): function

A fetch implementation

#### Details

In this example we define an object `requestOptions` with an async function in the `headers` property. This function
gets a JWT refresh token and updates the JWT access token allowing the renderer to keep displaying the
pricing:
```jsx
const requestOptions = {
  headers: async () => ({ 'Authorization': `Bearer ${await refreshAccessToken()}`})
}

<PricingRenderer src="https://acme.cloud.com/products/acme/pricing" request={requestOptions} />
```

### visibility

The `visibility` prop controls the renderer visibility of plans and add-ons.

#### Signature

[View source](https://github.com/javiercavlop/pricing-renderer/blob/27c6c673ed63b3044faeb25931cf73a9ee81e469/src/react/index.ts#L75).
```typescript
visibility?: 'public-only' | 'all'
```

- When `visibility` is `public-only`, **ONLY** public plans and add-ons will be displayed. A plan or add-on is public if
`plans|addOns.<name>.private` is absent or set to `false`.
- When `visibility` is `all`, **ALL** add-ons and plans will be displayed in the renderer
whether the [plan](../../../pricing-description-languages/Pricing2Yaml/versions/pricing2yaml-v31-specification.mdx#plansnameprivate)
or [add-on](../../../pricing-description-languages/Pricing2Yaml/versions/pricing2yaml-v31-specification.mdx#addonsnameprivate)
is `private` or not (see `private` prop in the Pricing2Yaml Specification).
- `visibility` defaults to `public-only`.

#### Details

All plans and add-ons will be displayed ignoring the status of the `private` property.
```jsx
<PricingRenderer pricing={pricing} visibility="all"/>
```
