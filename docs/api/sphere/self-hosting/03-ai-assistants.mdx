# Enable the AI assistants

SPHERE works without any language model. Three features use one, and each instance chooses which model serves them:

| Feature | What it does | What it needs |
| --- | --- | --- |
| **ORBIT's chat** | Reads your workspace and proposes changes as plans you confirm | A model, nothing else: ORBIT is part of the SPHERE API |
| **HARVEY** | Answers questions about pricings | A model and the AI services |
| **A-MINT** | Extracts a pricing from a pricing web page | A model and the AI services |

ORBIT's MCP server, at `/api/v1/orbit/mcp`, calls no model, so it works in every instance: assistants such as Claude or ChatGPT connect to it with an API key or OAuth (see the [SPHERE ORBIT plugin](https://github.com/SCORELabUS/sphere-orbit-plugin)).

The AI services (HARVEY, A-MINT, two analysis engines and a pricing MCP server) come from the [Pricing Intelligence repository](https://github.com/SCORELabUS/Pricing-Intelligence-Interpretation-Process). SPHERE pins their images by version and digest; they run on `amd64` only (on Apple Silicon, Docker emulates them).

## With OpenAI

Put an OpenAI API key in the `.env` file and start the `ai` profile.

**Your own instance** (`docker/self-hosted`):

```bash
# .env
OPENAI_API_KEY=sk-...
```

```bash
docker compose --profile ai up -d
```

**The local demo** (`docker/testing`):

```bash
echo "OPENAI_API_KEY=sk-..." > .env
docker compose -f docker-compose.yml -f docker-compose.ai.yml up -d
```

With the key alone, without the `ai` profile, ORBIT's chat works; HARVEY and A-MINT also need the AI services.

## With a self-hosted, OpenAI-compatible model

HARVEY, ORBIT and A-MINT can use any API compatible with OpenAI's instead of OpenAI itself: [Ollama](https://ollama.com), [vLLM](https://docs.vllm.ai), LM Studio or another compatible provider. Set these variables in the same `.env`:

| Variable | Used by | Default |
| --- | --- | --- |
| `OPENAI_BASE_URL` | HARVEY, ORBIT and A-MINT: base URL of the API, ending in `/v1` | `https://api.openai.com/v1` |
| `OPENAI_API_KEY` | HARVEY, ORBIT and A-MINT: key for that API | None |
| `OPENAI_MODEL` | HARVEY and ORBIT | `gpt-5-nano` |
| `AMINT_LLM_MODEL` | A-MINT, to extract pricings | `gpt-5.2` |
| `AMINT_LLM_BETTER_MODEL` | A-MINT, for its higher-quality steps | `gpt-5.2` |

A server that needs no key, such as Ollama, still needs a value in `OPENAI_API_KEY`: without one, the assistants report that they are unavailable and A-MINT extracts nothing.

For example, with Ollama serving `qwen3:32b` on the same machine as Docker:

```bash title=".env"
OPENAI_API_KEY=ollama
OPENAI_BASE_URL=http://host.docker.internal:11434/v1
OPENAI_MODEL=qwen3:32b
AMINT_LLM_MODEL=qwen3:32b
AMINT_LLM_BETTER_MODEL=qwen3:32b
```

Then start the AI services as above. `host.docker.internal` reaches the host from the containers with Docker Desktop. On Linux, add this to the `server`, `harvey` and `a-mint` services, or use the host's address on the network instead:

```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

A model served from another machine only needs its URL in `OPENAI_BASE_URL`.

:::warning Choose a capable model
The model must support tool calling (function calling) and JSON output. ORBIT sends OpenAI-style `tools` and `response_format: json_object`; HARVEY plans its tool calls as JSON and sends `reasoning_effort: "high"`, which the server must accept or ignore. Small models often fail at both. The published quality of HARVEY, ORBIT and A-MINT was measured with commercial OpenAI models, so expect different results with other models.
:::

## Limits on ORBIT

ORBIT shares its model with HARVEY, so it caps its own traffic: by default 20 messages a minute for all users together, and 10 an hour per user. Past the hourly limit, ORBIT points users to the [SPHERE ORBIT plugin](https://github.com/SCORELabUS/sphere-orbit-plugin), which lets them use their own Claude or ChatGPT through the MCP server.
